## 1. 一句话目标

让一个没读过 README 的人，在手机浏览器里 30 秒内开始第一幕，30 天内走完一次完整的嘉祐二年赶考，并相信其中的制度、人物、诗句都有出处。

## 2. 范围（做）

| 层 | 内容 |
|---|---|
| 玩法 | 30 日行程、每日 4 行动点、三属性衰减、6 个随机事件 + 2 场固定遭遇、省试三场 + 殿试、4 条失败线 |
| 内容 | 12 幕、5 位大儒座谈、18 个题诗题材、150 道题、57 个词条 |
| 史料 | 词条分「据 / 推断 / 设」三档；史事晚于 1057 的题不得进考场 |
| 工程 | 单文件离线可玩；`dist/` 拆分版上 Cloudflare Pages；四层测试 |
| 展示 | 一页 HTML 架构图（`docs/architecture-explainer.html`）、`docs/evidence.md`、`docs/user-feedback.md` |

## 3. Non-goals（明确不做）

1. **不做多人、不做联网对战**：单文件离线是核心卖点，也是零成本部署的前提。
2. **不引入前端框架与构建链**：保持"双击即玩"，`build.py` 是唯一构建步骤。
3. **不做真实 LLM NPC**：不引入 API Key、不引入 Worker 计费；人物台词全部预写并标出处。
4. **不追求诗评的精确性**：判分是近似规则，README 已声明；不因个案改到过拟合。
5. **不重做美术**：本轮只补资源与版面，不换画风。
6. **不把 Godot 版塞进本周交付**：`godot/` 是实验分支，另行评估（见 `questions.md`）。
7. **不给 150 道题逐题标出处**（2026-11-14 拍板）：题库是通行历史知识，只承担题型；史料引证由 57 条词条承担，年代边界由 `afterCutoff` 承担。不在题目上挂"伪出处"。

## 4. 史料红线

- **年代**：以嘉祐二年（1057）为截断。`afterCutoff > 1057` 的题只存不用；省试、殿试抽题池均已过滤。
- **出处**：词条必须 `src` 非空；有原文引文才可标「据」，据书名转述标「推断」，游戏机制标「设」。
- **不造引文**：未核到原文的，只写到书名/篇名一级，用「所述」标明。
- **人物**：真实历史人物只出现在其可考的年份与地点（黄庭坚 12 岁、米芾 6 岁，此科不出场）。

## 9. Plan 模式问答记录（展示用，2026-11-14）

> 下面三问三答是规划阶段真实卡住过的分歧，不是事后补写的"标准答案"。
> 课堂上直接展示这一节 + 第 8 节的 `/goal`，就是 Loop 1 的"来回答疑"。

**Q1：单文件离线，还是拆成多文件换线上速度？**
A：两个都要，但不能各自漂移。`北宋赶考记.html` 保留 base64 内嵌，双击即玩；同一份模板用 `python3 build.py --dist` 生成 `dist/`（WebP 外链 + 缓存头）给 Cloudflare。验收看第 6 节第 6 条：线上首屏 ≤ 5 s。

**Q2：150 道题要不要逐题标出处？**
A：不标。四选一题干多是概括，硬挂书名会制造"伪出处"；题库只承担题型，史料引证集中在 57 条词条（据/推断/设），年代边界用 `afterCutoff`。对外口径写在 `docs/evidence.md` §3。

**Q3：大儒对话要不要接 LLM，做成真自由对话？**
A：这周不做。真自由要 Worker + Key + 限流 + judge 日志 + 离线兜底，11·18 前风险太高；先保留 15 个话题，半自由（本地意图匹配 + 记忆 + 人设）方案留到 Week 12。见 `questions.md`。

**Q4：省试三场叫"诗赋 / 论 / 策论"，题却是四选一，算不算史实错误？**
A：算"题型折中"，不算史实错误。制度名目据《宋史·选举志一》校正（专场经义是熙宁后之制），题型在 README 与 evidence 里如实声明为现代四选一。
